# 5단계 결과 — 구 기록 이전·내보내기·초기화

완료일: 2026-10-30  
범위: 구 준비 기록의 안전한 이전, 준비 JSON 내보내기, 초기화 정책과 결과 안내.

## 변경 파일

| 파일 | 내용 |
|---|---|
| `static/js/store.js` | 원본 체크 이전, 저장 성공 후 완료 표시, 실패 재시도, 준비 내보내기, 전체 초기화 |
| `static/js/tools.js` | 내보내기·초기화 버튼명, 삭제 범위 확인 문구, 초기화 저장 성공/실패 안내 |
| `tests/store.cjs` | 기존 24개에 이전·내보내기·초기화 22개를 추가해 총 46개 검증 |
| `docs/stage-5-result.md` | 이 단계 결과 |

app1 및 참조 원본은 수정하지 않았다. index와 데이터 파일은 이번 단계에서 변경하지 않았다.

## 이전 규칙

1. 현재 vcl:v1을 정상적으로 읽은 경우 같은 출처의 `vibe_coding_checklist_state`를 확인한다. 현재 저장이 손상되었거나 읽기 차단 상태라면 자동 이전 저장을 시도하지 않는다.
2. 원본은 정확히 12개 boolean 배열인 경우만 받는다. JSON 오류, 다른 컨테이너, 길이·항목 타입 오류는 건너뛴다. 잘못된 원본 JSON 자체를 저장 차단으로 표시하지 않는다.
3. setup.js의 `legacyCheckIds` 순서로 기존 12개 체크만 채운다. 새 저장에 true 또는 false가 명시된 항목은 그대로 둔다.
4. Codex 체크를 Antigravity 기록으로 만들지 않는다. 직군·AI 선택·배포 여부도 추정하지 않는다. 기존에 정상 선택값이 있으면 유지한다.
5. 변환 상태와 `migrations.setupChecklistV1 = true`를 하나의 vcl:v1 setItem에 함께 저장한다. 내부 이전 이력은 setup 선택값과 분리한다.
6. 저장이 실패하면 디스크에 완료 표시를 남기지 않는다. 현재 창의 변환 체크는 임시로 유지하고 다음 정상 변경의 저장에서 다시 시도한다. 재시도 전 수동으로 고친 체크도 보존한다. 새로고침으로도 이전을 재시도할 수 있다.
7. 완료 표시가 이미 있으면 반복 이전하지 않는다. 이후 원본 키의 체크가 바뀌어도 새 기록을 덮지 않는다. 원본 키를 삭제하거나 수정하지 않는다.

legacy 키 읽기 자체가 차단된 경우 현재 학습 상태는 유지하고 persistent를 false로 알린다. 읽기 제한이 해제된 뒤 새로고침하면 다시 확인한다. 다른 도메인·포트·file://는 현재 출처의 localStorage에서 읽을 수 없으므로 자동 이전하지 않는다. 파일 가져오기 기능은 추가하지 않았다.

## 내보내기

기존 exportedAt·progress·favs를 유지하고 정규화된 setup 선택·체크를 추가했다. 명시적인 false도 포함한다. 저장 차단 중에는 현재 창의 임시 준비 상태를 내보낼 수 있다. 내부 migrations 이력은 사용자 학습 JSON에 포함하지 않는다.

버튼명은 “학습·준비 기록 내보내기 (JSON)”로 변경했다. 기존 다운로드 파일명과 브라우저 파일 생성 방식은 유지했다. 앱이 인증 키·파일을 수집하거나 내보내는 기능은 없다.

## 초기화

- 삭제: 학습 진도, 퀴즈, 학습 체크, 즐겨찾기, 마지막 학습 위치, 준비 직군·AI 도구·배포 여부·체크.
- 유지: 정상 테마와 내부 이전 이력. 원본 앱의 준비 키는 보존한다.
- 이전 기록이 아직 없거나 이전이 실패했던 상태에서 초기화해도, 성공한 초기화 저장에 이전 종료 표시를 함께 남긴다. 나중에 원본 준비 키가 발견되어도 초기화한 기록을 되살리지 않는다.
- reset은 디스크 저장 성공 여부를 반환한다. 실패한 경우 현재 창에서는 초기화하지만 디스크에는 이전 값이 남는다. UI는 “이번 창에서 초기화했지만 저장하지 못했으며 새로고침하면 이전 기록이 다시 나타날 수 있다”고 알린다.
- 저장 실패 후 같은 창에서 다시 저장하면 초기화 상태와 이전 종료 표시를 함께 저장한다. 실패한 초기화가 새로고침 후에도 유지된다고 보장하지 않는다.

내 학습의 확인 문구를 위 범위와 맞추고 취소 시 변경하지 않는다. 이 단계의 UI 변경은 기록 관리 문구·핸들러에 한정하며 별도의 준비 현황 화면은 아직 추가하지 않았다.
