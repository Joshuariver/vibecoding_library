## 1. 결론 요약

`docs/additional_concepts.md`의 세 주제를 기존 101·102 과정의 가이드와 **체험관 실습 3개**에 나누어 배치하는 안을 권장한다. `main.py`는 정적 파일 제공만 담당하므로 서버 라우트나 새 학습 레벨을 만들 필요는 없다. 기존 가이드 절 ID를 유지하되, 신규 실습으로 인한 진도율 변화는 검증한다.

세 실습은 기존 체험관의 단일 HTML·sandbox iframe·테마·높이 알림·`lab-engaged` 메시지 규약을 따른다. `static/js/app.js:300-345`의 수동 완료·취소 버튼도 그대로 사용할 수 있게 설계한다. 실습별 명확한 상호작용을 완료 신호의 근거로 삼고, 단순 클릭 횟수만으로 이해도를 판정하지 않는다.

위 배치에 맞춰 **검색 항목도 함께 갱신**해야 한다. `static/data/search.js`의 기존 가이드·용어·프롬프트·실습 검색 항목은 콘텐츠 데이터 변경만으로 자동 갱신되지 않는다. `마크다운`, `메타 프롬프팅`, `문맥 내 학습`, `ICL`, `RAG`, `CPT` 검색어가 가이드와 해당 실습으로 이동하도록 반영한다. 실습 결과 주소는 `#/101/labs/11`, `#/102/labs/17`, `#/102/labs/18`을 사용하고 기존 가이드 절 ID도 유지한다.

## 4. 콘텐츠 다듬기 제안

1. 마크다운의 장점은 **문서 구조와 가독성, AI에 전달할 때의 명확성**으로 설명한다. 원문의 “AI 학습 데이터로 매우 효율적”, “더 정확히 학습”은 모든 모델·작업에서 보장되는 효과처럼 읽힐 수 있으므로 단정 표현을 줄인다.
2. “Markdown을 PDF·HTML로 배포”는 **별도 변환 도구나 확장을 사용하면 가능**하다고 조건을 명시한다. 앱이 직접 변환하는 기능으로 안내하지 않는다.
3. 메타 프롬프팅은 좋은 결과나 환각 감소를 보장하는 기법으로 표현하지 않는다. 재사용 템플릿을 만든 뒤 실제 업무 예시로 시험하고 사실·출처를 검증하는 단계까지 넣는다.
4. ICL은 실행 시 입력에 예시·자료를 제공하는 방식이며, RAG는 관련 자료를 찾아 입력에 제공하는 방식으로 구별한다. CPT는 추가 학습으로 모델 가중치가 바뀌는 방식이라는 차이를 표로 보여준다. 원문의 “30페이지 제품 매뉴얼”은 모델의 입력 한도와 문서 품질에 따라 달라지는 **예시**로 표시한다.
5. 원문의 용어·맞춤법(`Hallucinaton`, `CPT:지속 사전 학습`, 띄어쓰기 등)을 정리하고 기존 앱의 한국어 용어 표기와 맞춘다.

## 5. 수정 범위 및 영향

- **권장 범위:** `static/data/level-101.js`, `static/data/level-102.js`, `static/data/glossary.js`, `static/data/prompts.js`, `static/data/labs.js`, `static/data/search.js`의 관련 항목과 신규 `static/labs/101-11.html`, `static/labs/102-17.html`, `static/labs/102-18.html`. 필요 시 실습 수와 콘텐츠 위치를 설명하는 `README.md`도 함께 갱신.
- **기존 절 ID 유지:** `s2`, `s3`, `s4` 등에 내용을 추가한다. 절을 새로 만들면 진도율의 분모가 바뀌고 기존 저장 기록의 표시가 달라질 수 있으므로, 현재 제안에서는 새 절을 만들지 않는다.
- **실습 진도 영향:** 101 실습은 10개에서 11개, 102 실습은 16개에서 18개로 늘어난다. 기존 완료 기록은 ID별로 보존되지만 완료율의 분모가 커져 기존 사용자의 표시 진도율이 낮아질 수 있다. 이 영향과 103 잠금 조건(102 체크리스트 완료 기준)이 서로 독립인지 확인한다.
- **퀴즈:** 신규 퀴즈 문항은 이번 제안에 포함하지 않는다. 새 체험관의 결과는 학습용 피드백이며 공식 정답률·자격 판정으로 표시하지 않는다.
- **서버·배포:** `main.py`, `Dockerfile`, 의존성, 환경 변수, 저장 형식은 변경 대상이 아니다. 정적 자산 변경이므로 배포 시에는 변경된 파일이 포함되는지 확인한다.

## 6. 승인 후 검증 계획

1. 101·102 가이드, 용어 사전, 프롬프트 화면에서 새 내용·링크·복사 동작을 확인한다.
2. 세 신규 실습의 가이드 연결, URL, 상호작용 결과·해설, 완료·취소, iframe 높이·테마·오류 메시지를 확인한다. 사용자 입력의 HTML이 실행되지 않는지도 확인한다.
3. 통합 검색에서 위 여섯 검색어와 영문 약어로 가이드 및 신규 실습 결과가 나타나는지 확인한다. 관련 검색 테스트(`tests/search.cjs`)를 갱신하고 실행한다.
4. 기존 `vcl:v1` 학습 기록을 가진 상태에서 기존 실습 완료 ID의 보존, 신규 실습 수에 따른 101·102 진도율 변화, 103 잠금 조건을 확인한다. 기존 저장·라우팅 테스트를 실행한다.
5. 데스크톱·모바일에서 긴 비교표·코드 블록·실습 입력 영역이 가로 넘침 없이 읽히고 키보드로 조작되는지 확인한다.
6. 실제 테스트 실행 결과와 미확인 항목을 수정 후 보고한다. 이 문서는 제안 단계이므로 현재 테스트 통과를 주장하지 않는다.

## 7. 확인 필요

제안은 **기존 절에 분산 배치하고 체험관에 독립 실습 3개를 추가**하는 안이다. 기존 사용자의 실습 진도율이 낮아질 수 있으므로 이 변화를 수용할지 승인 시 확인이 필요하다. 한 화면에서 세 주제를 연속으로 읽는 별도 특집 페이지를 원한다면 새 화면·주소·검색·진도 정책을 함께 설계해야 하므로 수정 범위가 커진다. 콘텐츠 편집과 앱 수정은 이 제안서에 대한 사용자 승인 후 시작한다.
