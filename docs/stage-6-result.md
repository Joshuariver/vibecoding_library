교육 화면을 메뉴에서 열 수 있도록 계획 9단계의 시작하기 메뉴 연결 중 최소 부분을 앞당겼다. 홈 바로가기·검색·내 학습의 준비 현황은 아직 연결하지 않았다. 모바일 하단 메뉴는 기존 5개를 유지한다.

## 구현한 화면

- `#/courses`: 저장 직군이 없으면 두 과정 선택. 저장값이 있으면 해당 과정 안내.
- `#/courses/sales`, `#/courses/dev`: 명시된 직군 우선. 선택 직군을 준비 상태에 저장하며 기존 체크·학습 위치는 유지.
- 직군 탭은 실제 주소를 가진 링크이며 선택 상태를 aria-current로 표시한다. 화면 전환 시 기존 제목 포커스 처리를 사용한다.
- 순서: 직군·요약 → 교육 일정·신청 정보 → 학습 목표 → 시간표 → 준비사항 → 문의처 → 관련 고급 학습 경로.
- 지난 회차·신청 기간 종료를 명확히 표시하고 러닝넷 검색명을 원문대로 제공한다. 확인되지 않은 신청 URL이나 신청 버튼을 만들지 않는다.
- 고급 경로는 기존 isUnlocked로 판정한다. 미완료자는 102 체크리스트 완료 조건을 안내하며 교육 안내와 준비 진입은 항상 가능하다.
- `#/setup`, `#/setup/sales`, `#/setup/dev`: 준비 진입 안내와 도구 5개·Git 필수 조건·101 시작·교육 안내 복귀를 제공한다. 실제 도구 선택·설치 카드·체크·준비율은 7단계에서 연결한다.
- 잘못된 직군·추가 경로는 안내와 과정 선택으로 돌아간다. 저장 직군을 근거로 잘못된 URL을 조용히 다른 과정으로 바꾸지 않는다.
- 저장 차단 시 임시 상태라는 안내를 새 화면에도 표시한다. 인증·설치 명령을 실행하지 않는다.

신규 화면은 기존 상단바·사이드바·본문·Pretendard·색상·카드·탭을 재사용한다. ref_app의 헤더·스타일·브랜드 색을 복사하지 않았다. 문의처는 공통 데이터에서 참조하고 원본 연락처의 현재 운영 확인이 필요하다는 문구를 유지한다.

## 모바일 수정

실제 Chrome의 390px 검사에서 시간표의 520px 최소 너비가 그리드 본문까지 확장해 페이지 폭이 552px이 되는 문제를 발견했다. 신규 화면일 때만 main에 onboarding-view 클래스를 적용하고 min-width:0으로 축소를 허용했다. 표는 포커스 가능한 내부 스크롤 영역으로 유지한다. 수정 후 페이지 전체 가로 넘침이 없어졌다.

이 변경은 교육·준비 화면에 한정하며 기존 학습 레이아웃의 전역 최소 너비를 바꾸지 않는다.

브라우저 검사에서는 로컬 서버를 루트와 `/project/academy/test-user/proxy/8000/` 접두 경로로 각각 실행했다. 이 브라우저 검사는 접두 경로를 유지하는 요청을 확인했으며 접두 경로 제거/유지의 HTTP 경우는 기존 HTTP 검사에서 확인했다. 실제 DEJ 게시 환경에서 검증한 결과는 아니다.

Python 3.13.7·Node.js 24.18.0·기설치 Chrome/Playwright를 사용했다. 기존 Puppeteer 경로가 없는 환경에서 새 패키지 설치 없이 대체했다. Python 3.12 실행 검증, 전체 실습 상호작용, 최종 접근성·검색 흐름은 이후 회귀 단계에 남아 있다. HTTP의 기존 httpx 사용 중단 예정 경고 1개는 유지된다.

브라우저 검사 최초 실행의 URL assertion은 설치된 Python API에 맞춰 정규식으로 정정했다. 최종 검사는 모두 통과했고 테스트용 서버·브라우저는 종료했다. 사용자 브라우저의 기존 프로필·기록은 사용하지 않았다.
